    NUCLEO-L552ZE-Q

    The NUCLEO-L552ZE-Q with an STM32L552ZET6Q (Cortex-M33, Armv8-M, 110 MHz max): 512 KiB of flash at 0x08000000, 192 KiB SRAM1 at 0x20000000 plus 64 KiB SRAM2 at 0x20030000, three user LEDs on PC7 (LD1, green), PB7 (LD2, blue) and PA9 (LD3, red), a user button on PC13, and the ST-LINK/V2-1 Virtual COM Port on LPUART1 PG7/PG8 (AF8).

    This is the first STM32L5 part in the engine. It is an L1 (smoke) target: boot, the new L5 RCC clock gates, the LPUART1 console and the GPIO LED/button path (with ODR read-back) are proven by a committed smoke fixture and an io-smoke.yaml. Unmodified upstream Zephyr v3.7.0 hello_world (the sample Renode's ARMv8M.robot boots) also runs through Zephyr's own L5 clock/ICACHE/DBGMCU bring-up and prints on LPUART1, and stock synchronization runs its two-thread semaphore hand-off on SysTick timeouts and PendSV context switches. Stock tests/kernel/fpu_sharing/generic (Renode's ARMv8M.robot FPU sharing case) passes 2/2 on the modelled FP context (CONTROL.FPCA, extended exception frames) and the PMSAv8 MPU region file that TT reports from. Stock tests/kernel/mem_protect/protection (Renode's ARMv8M.robot protection case) passes 5/5: the MPU is enforced, so a store to the read-only flash region and a fetch from execute-never SRAM raise MemManage. Stock tests/kernel/mem_protect/userspace (Renode's userspace case) passes all 40 cases in its three suites: user threads run unprivileged, kernel memory and the PPB are closed to them, MSR cannot clear CONTROL.nPRIV, and TTT reports the unprivileged view that syscall buffer checks use. All four Renode ARMv8M.robot cases now run. There is no silicon capture: SIM-DERIVED, no executing-fidelity differential.

    Not claimed yet

    TrustZone / SAU / GTZC and the secure/non-secure split are not modelled. The PMSAv8 MPU is enforced for data accesses and instruction fetches (MemManage DACCVIOL/IACCVIOL), but MAIR memory types, faults on exception stacking (MSTKERR/MUNSTKERR) and lazy FP preservation (MLSPERR) are not (ISA coverage). FP state is stacked eagerly, not lazily (FPCCR.LSPACT reads 0). The L5 non-secure FLASH controller, EXTI, ADC, FDCAN and USB are declared stubs.

    DMA1 / DMA2 / DMAMUX1 0x4002_0000 / 0x4002_0400 / 0x4002_0800 modelled — unexercised
    RNG / CRC / RTC / IWDG / WWDG / PWR see descriptor modelled — unexercised
    ICACHE 0x4003_0400 modelled — the U5 icache model (same IP); Zephyr enables it
    DBGMCU 0xE004_4000 modelled — IDCODE 0x2001_6472 (DEV_ID 0x472, rev Z)
    FLASH controller, EXTI, ADC1, FDCAN1, USB see descriptor type: stub — zeros (so FLASH_ACR.LATENCY does not read back)
    FP extension (FPCCR/FPCAR/FPDSCR/MVFR) 0xE000_EF34 modelled — cortex_m_fpu: CONTROL.FPCA, extended frames (eager)
    MPU (PMSAv8, 8 regions) 0xE000_ED90 modelled + enforced — armv8m_mpu: AP/XN/PRIVDEFENA/HFNMIENA, MemManage with MMFAR; reported by TT
    TrustZone / SAU / GTZC — not modelled

    Boot path

    Fast boot. The engine loads the ELF and enters it at its entry point (vector table at the flash base, 0x0800_0000). The initial SP is word 0 of the firmware's vector table — 0x2003_0000, the top of SRAM1 in the smoke's memory.x — not an engine default. The STM32 system-memory bootloader and TrustZone secure-boot path are not modelled.

cargo build -p firmware-l552ze-smoke --release --target thumbv8m.main-none-eabi
./target/release/labwired test --script examples/nucleo-l552ze-q/io-smoke.yaml --no-uart-stdout
# stock Zephyr hello_world + synchronization (committed fixtures)
./target/release/labwired test --script examples/nucleo-l552ze-q/zephyr-hello.yaml
