    Luckfox Pico Mini A

    Source-grounded onboarding dossier for the RV1103 board and a battery-powered smart basket prototype.

    Experimental, below L0. The generic RV1103 chip and Mini A system descriptors declare CPU/memory geometry only. The separate optional rv1103-linux native CLI passed a reduced direct zImage boot to real PID1 on 2026-10-12, using privileged Cortex-A7/MMU, SystemBus, GIC400, architectural timer and DW UART2. This leaves board reset, SD/vendor BSP and physical acceptance open. The older qemu-arm ELF adapter remains an instruction fixture. See the Linux receipt and scope, support rubric, and validation record.

    Status at a glance

    Item Status
    Exact hardware Luckfox Pico Mini A, not Mini B
    Vendor silicon RV1103; Cortex-A7, up to 1.2 GHz; 64 MB DDR2
    Storage MicroSD boot; Mini A has no populated SPI NAND
    Mechanical reference 21.00 × 28.14 mm; 2.54 mm side-pin pitch
    Local emulator Optional qemu-arm-system reduced Linux CLI; separate qemu-arm ELF fixture
    Mini A target support Below L0; reduced virtual Linux boot passed, board/BSP and physical checks pending

    Flash / firmware artifact

    For physical hardware, follow the vendor MicroSD flash instructions and select the Mini A MicroSD image. Record its download URL, version, SHA-256, board revision and serial boot log. No vendor OS image has been downloaded, flashed or booted as part of this dossier.

    The official SDK is LuckfoxTECH/luckfox-pico. Select the RV1103 Mini board and SD-card boot with the SDK's board selector; verify the resulting device tree is for Mini A (rv1103g-luckfox-pico-mini-a.dts). The device-tree guide lists Mini A and Mini B separately. A Linux application ELF is not the bare-metal ARM instruction fixture described below.

    Pins (board label → GPIO)

    The vendor uses this shared Mini A/B illustration for the interface layout; its photographed board has a NAND package. It is not a photograph of the Mini A population. Download original pinout.

    All 22 numbered side pads below were transcribed from this image. _d/_z suffixes are retained exactly as printed, without interpreting them as voltage ratings. Alternate functions require correct pinmux; they are not simultaneously active.

    The illustration also labels ACT as GPIO3_C6_d and USER as GPIO1_A2; these are not additional numbered header pads. Five separate bottom pads carry Ethernet TXP/TXN/GND/RXP/RXN. Neither analog-input electrical limits nor output-rail current capacity can be inferred from this image.

    The official schematic identifies the SARADC/PWM VCCIO2 domain as 1.8 V only. Header pads 19/20 (GPIO4_C0/C1) belong to that domain; do not apply 3.3 V or a battery voltage. The selected UART4/I2C3 connections use the separate 3.3 V domain. The schematic also requires SARADC_IN0 to remain pulled up; preserve that board function when considering pad 19. Absolute maximum ratings and ADC behavior still require the silicon documentation.

    For the basket, reserve 14/15 for ADXL345 I2C3 and 10/11 for ESP-AT UART4. Optional flow control uses 17 CTS / 16 RTS. Preserve 4/5 UART2 for recovery and boot logs. See complete wiring and power notes. The vendor I2C and UART guides corroborate the Mini A/B interface selection.

    Battery, charging, RF and enclosure ❌ Engineering proposal; no bench results
    Browser / Playground / MCP execution ❌ Native core experiment has no browser support

    What it catches vs bench

    The reduced Linux platform catches privileged CPU, MMU, GIC/timer/console and real guest syscall integration failures. Its receipt proves cold direct zImage decompression and PID1 sleep with advancing uptime. It does not measure physical serial timing, Wi-Fi association, motion sensing, charging or battery runtime. The separate older ELF fixture exercises bounded instructions and shared memory-bus plumbing; it does not provide this Linux route.

    How to run (CLI · Playground · MCP)

    The chip descriptor, system manifest and example manifest declare CPU and memory geometry. They do not provide a Mini A boot/run command. For the instruction-only experiment, use the native-feature commands and receipts in QEMU ARM core prototype with examples/cortex-a7-core. Its synthetic memory map is not the RV1103 memory map. Playground and MCP board execution remain unavailable.

    For the separate reduced Linux platform, follow the native zImage preparation/build/gate commands. Its backend is optional, Linux x86_64 GNU only, and requires panic unwind; default CLI and browser builds remain independent of it.

    Joint native basket evidence

    The joint Linux basket receipt and reproduction add native-only ADXL345 I2C3 and behavioral UART4 integration through actual Machine/SystemBus/CosimSession plus one persistent reduced power plant. Actual 644.13082329 wall seconds / 89 functional-clock seconds at fixed 24MHz is not 1x performance. Recovery uses a fresh CPU/bus/controllers/components with the SAME plant, battery and time. Register retention applies only within one external cut/restore fixture. Raw5V maps to synthetic execution VDD; raw3V/effective external domain uses functional2.7V. Carrier disconnect and latch reset are explicit interventions. Browser/default still refuse Linux; full RV1103/vendorBSP/SD/ROM/RF/all50silicon/physical acceptance remain unavailable.
