    End-to-end mixed-signal board coverage

    Generated by scripts/analog_board_coverage.py. Do not edit by hand; rerun the script after adding or removing a board test.

    A profile is covered only when an integration test advances a CosimSession that loads that profile (or one of its examples/<dir>/analog-*.yaml decks) and reaches an endpoint route the manifest declares: board.analog.<pad>_volts, which the chip's analog_pins: map or the pad's adc pin function resolves to an ADC channel, or an explicit adc.<peripheral>.<channel>_volts route. Device-only unit tests, ADC register tests with no netlist, files that only list fixture paths, and helper tests do not count: they prove the model, not the board.

    • Profiles in configs/systems/: 442
    • Covered end to end: 143
    • Not covered: 299
    • Not covered but with an ADC pad map: 0 (these are the boards the generic NTC and diode decks can reach next; the rest need an analog_pins: block or adc pin functions, an ADC model, or a digital endpoint first)

    The Analog pad map column counts the pads a chip can hand to an ADC: analog_pins: entries plus pads whose pins: table carries an { type: adc, peripheral, channel } function (the union the router uses). Every such entry in this tree names an ADC peripheral, so the count is what the generic decks can reach without new routing.

    How to add a board

    1. Add examples/<board>/analog-ntc-diode-system.yaml with the generic Beta NTC divider and the Shockley diode load line, routing to board.analog.<pad>_volts.
    2. Add a test under crates/core/tests/analog/ that loads the profile, solves the netlists, compares each solved node against an independent closed form, advances the session to a boundary, and asserts the firmware-visible endpoint (ADC data register or input level).
    3. Rerun this script and commit the regenerated document.

    Reference solver

    examples/nucleo-f401re/analog-ntc-diode-ngspice.yaml is the same deck shape with both models on adapter: ngspice. ntc-beta.cir writes the Beta NTC as a behavioural current and diode-load-line.cir keeps the in-core diode model card; the manifest keeps the same ui.ntc.temperature_c input and board.analog.pa0_volts / pa1_volts routes. The diode deck pins .options temp=26.85 tnom=26.85 to match the in-core engine's 300.00 K.

    labwired cosim-step examples/nucleo-f401re/analog-ntc-diode-system.yaml \
  --set ui.ntc.temperature_c=25 --steps 4 --json
labwired cosim-step examples/nucleo-f401re/analog-ntc-diode-ngspice.yaml \
  --set ui.ntc.temperature_c=25 --steps 4 --json

    crates/cli/tests/analog_vs_ngspice_differential.rs compares the two runs and requires the NTC output to change with temperature. It is a solver-parity check for this shape, not evidence that every board listing above has been re-run on ngspice.
