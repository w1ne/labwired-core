# Release v0.27.0: More hardware and analog simulation

LabWired Core v0.27.0 expands hardware simulation and analog input coverage. The capabilities below describe tested model behavior; they do not imply complete silicon or physical-board validation.

## Hardware and firmware

- **CH32V203C8T6:** Run unmodified ch32fun blink, debug-print and SysTick interrupt examples. The simulator also models tested paths for external interrupts, USART, SPI DMA, timers and ADC conversions. I2C, CAN and USB remain unmodeled. [Firmware tests](https://github.com/w1ne/labwired-core/pull/2245), [ADC](https://github.com/w1ne/labwired-core/pull/2271).
- **CH32V003:** Extend the existing model with I2C and SPI master paths, PWM and analog inputs. The I2C test runs the stock WCH Arduino Wire library against a BME280, with an incorrect-address negative control. [I2C](https://github.com/w1ne/labwired-core/pull/2201), [SPI](https://github.com/w1ne/labwired-core/pull/2218), [PWM](https://github.com/w1ne/labwired-core/pull/2192).
- **ESP32 analog inputs:** ADC pin maps extend circuit simulation to ESP32-C3, C6, C5, C61 and S3 board profiles. C5 and C61 tests exercise thermistor and diode circuits through modeled ADC inputs. Some C5/C6 ADC channels and the C5/C61 SARADC clock gate remain unmodeled. [C5 and C61](https://github.com/w1ne/labwired-core/pull/2264), [C3](https://github.com/w1ne/labwired-core/pull/2248), [C6](https://github.com/w1ne/labwired-core/pull/2255), [S3](https://github.com/w1ne/labwired-core/pull/2251).

## Analog simulation

- Expand ngspice differential checks to coupled inductors, a PNP stage, a CMOS inverter and a P-channel JFET follower. The checks compare specific circuits and do not establish general SPICE equivalence.
- Add source identity and bounded input ranges to supported ngspice-backed Flex models. See the [changelog](https://github.com/w1ne/labwired-core/blob/main/CHANGELOG.md) for test scope.

## Migration

P-channel JFET `VTO` now follows the SPICE convention. A deck written for the old positive convention must use a negative value; for example, change `PJF(VTO=+2)` to `PJF(VTO=-2)`.

## Known limitations

- ESP32-S3 I2C pad routing has an open wrong-pin negative-control issue. Do not use this path to establish board pin-map correctness until [#1958](https://github.com/w1ne/labwired-core/issues/1958) is resolved.
- A per-board performance gate reports regressions; workload effects differ. See [#2094](https://github.com/w1ne/labwired-core/issues/2094).
- Firmware and peripheral results refer to the specified simulator tests. They do not imply radio propagation, full hardware coverage, or physical-device validation.
