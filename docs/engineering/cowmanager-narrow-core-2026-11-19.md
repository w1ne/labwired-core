# CowManager narrow Core compatibility — 2026-11-19

## Source scope

This integration starts at [941a6c5](https://github.com/w1ne/labwired-core/commit/941a6c5caf0c53b66aa5af9290e5ecba5972ec72), the A1 STM32 GPIO observer revision already selected by the application. It retains all 123 top-level chip YAML descriptors from that revision. No chip descriptor or coverage ledger is added or removed.

The ff78 regression uses this revision's flat `led_strip_system_configs`
integration target instead of the later grouped test layout. The only
production context adaptation in f57 places `sync_stm32_af_observers()`
immediately after `sync_pin_cells()` inside the existing SAM-only reset
block. No later F1 reset, LCKR or IDR behavior is imported. Both upstream
fixes are already ancestors of the retained private Core revision ddc48b.
The seven-file repair changes no descriptor, system manifest, firmware,
coverage ledger or threshold.

## Independent public and private revisions

The application public Core gitlink selects this narrow source tree for the
browser, open engine and generated public catalog. The builder selects the
Pro engine independently with
`LABWIRED_PRO_CORE_REV=ddc48b41198643c937d70c2050fee9a9cb395913` and retains
private model revision `f92e3b6f006061f97a4470eee480237fcfc00a0c`.

The builder copies runtime configurations from the public checkout and runs
them with the separately built Pro binary. Public and Pro Core revisions do
not have to match. The private Rust API is compiled within the retained
ddc/f92 binary. Private release acceptance pairs that binary with fresh
configurations and inputs exported from the final public application tree.

This public integration preserves the original 941a flash-owner API. It
adds no private runtime compatibility port.

## Historical silicon evidence

The A1 base changed `gpio.rs` but retained five legacy acknowledgement digests from its parent, [7ae9652f](https://github.com/w1ne/labwired-core/commit/7ae9652f717c428db3476caa2a8b0aa45abdcb8f). The original narrow candidate [ed5e2768](https://github.com/w1ne/labwired-core/commit/ed5e27681d991dc581bfbba219a6ecc126d47cf7) retained byte-identical watched model contents from 941a6c5 for STM32H563, L476, L073, F103 and F407. The BMA400 and CLI changes at that historical stage did not alter those watched paths.

That source-identity result does not describe the final integration: the f57 backport changes the watched `gpio.rs` model. The historical capture records still have no `silicon.models_digest`, so their source match remains **unverified**. No new acknowledgement or hardware capture is asserted for these GPIO changes. Their dates remain H563: 2026-08-10; L476, L073 and F103: 2026-08-09; F407: 2026-06-20.

The adopted 2026-11-12 upstream policy is already an ancestor of the application's previous broad candidate, `ddc48b41198643c937d70c2050fee9a9cb395913`. It reports missing capture hashes as **source match unverified**. ACK dates, ACK hashes and commit dates cannot establish a current silicon match. Source differences are informational; incomplete Git history, missing model watches, duplicate evidence keys, malformed capture records and stale generated reports remain errors.

All capture/acknowledgement metadata remain byte-unchanged. The manifest adds the explicit nRF5340 `nrf52/twim.rs` member required by the structural gate, following [d9ccc2624e](https://github.com/w1ne/labwired-core/commit/d9ccc2624efb5dae5bf77a9cabff49576439da05). The existing recursive `nrf52` directory watch remains in place. Manifest header comments also match the adopted upstream a0b0a91c policy; this comment alignment changes no parsed board data. The status document is generated by `scripts/generate_validation_status.py`; no hardware validation date or digest was invented.

## Released-CLI self-test boundary

The release-runner contract repair was validated with the SHA-verified
`labwired-cli 0.26.0` binary. With this older public L476 descriptor/ELF pair,
a 6,000,000-step run exits 0 without the required TIER1 marker. [Issue #2057](https://github.com/w1ne/labwired-core/issues/2057)
records the exact binary/input hashes and reproducer. Selecting the existing
F103 positive-control fixture does not repair or certify that L476 pair.

The self-test preserves all five controls. The existing F103 fixture emits
all nine TIER1 PASS markers and the done marker. The wrong F407 firmware
produces a BusFault and exit 3. The wrong-marker control still rejects a
valid CLI run that exits 0. Missing-chip and nRF marker checks remain in
place. The real coverage map, firmware files and step budget are unchanged.
