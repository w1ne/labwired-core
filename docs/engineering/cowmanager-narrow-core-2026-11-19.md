## Independent public and private revisions

The application public Core gitlink selects this narrow source tree for the
browser, open engine and generated public catalog. The builder selects the
Pro engine independently with
`LABWIRED_PRO_CORE_REV=ddc48b41198643c937d70c2050fee9a9cb395913` and retains
private model revision `f92e3b6f006061f97a4470eee480237fcfc00a0c`.

The builder copies runtime configurations from the public checkout and runs
them with the separately built Pro binary. Public and Pro Core revisions do
not have to match. The private Rust API is compiled within the retained
ddc/f92 binary. Private release acceptance pairs that binary with fresh
configurations and inputs exported from the final public application tree.

This public integration preserves the original 941a flash-owner API. It
adds no private runtime compatibility port.

## Historical silicon evidence

The A1 base changed `gpio.rs` but retained five legacy acknowledgement digests from its parent, [7ae9652f](https://github.com/w1ne/labwired-core/commit/7ae9652f717c428db3476caa2a8b0aa45abdcb8f). The watched model contents for STM32H563, L476, L073, F103 and F407 are byte-identical between 941a6c5 and this integration. The CowManager and flash changes do not touch those watched paths.

No exact later acknowledgement or silicon capture covers these narrow model digests. The capture records have no `silicon.models_digest`. Their historical dates remain H563: 2026-08-10; L476, L073 and F103: 2026-08-09; F407: 2026-06-20.

The adopted 2026-11-12 upstream policy is already an ancestor of the application's previous broad candidate, `ddc48b41198643c937d70c2050fee9a9cb395913`. It reports missing capture hashes as **source match unverified**. ACK dates, ACK hashes and commit dates cannot establish a current silicon match. Source differences are informational; incomplete Git history, missing model watches, duplicate evidence keys, malformed capture records and stale generated reports remain errors.

All capture/acknowledgement metadata remain byte-unchanged. The manifest adds the explicit nRF5340 `nrf52/twim.rs` member required by the structural gate, following [d9ccc2624e](https://github.com/w1ne/labwired-core/commit/d9ccc2624efb5dae5bf77a9cabff49576439da05). The existing recursive `nrf52` directory watch remains in place. Manifest header comments also match the adopted upstream a0b0a91c policy; this comment alignment changes no parsed board data. The status document is generated by `scripts/generate_validation_status.py`; no hardware validation date or digest was invented.

## Validation

The focused feature gate set contains three BMA400 smoke cases, the A1
observer case and the model-path integration case. The BMA400 analog case
uses the actual MNA solver; A1 covers forward/reverse pulses and
disabled/invalid-pin controls. The feature sources and these tests are
unchanged by the final public-only scope adjustment. Exact final-tree test
results belong to the Core CI and release receipts.

The full capture-provenance Python suite passed 56 tests. Its policy code,
board data and tests are unchanged by the final comment alignment. Normal
format, Clippy and host checks run for the final commit. The canonical
regeneration produced only the BMA400 peripheral-manifest/device-catalog
addition and the reviewed source/capture report; coverage scoreboards and
baselines did not change.

The static coverage receipts remain 107 chips proven by CLI gates and the
existing 12 declared exceptions (ceiling 12), plus 127 parts: 47
lab-exercised, 79 test-exercised, one device-only and no gaps. No chip
inventory or coverage limit was expanded.

Private acceptance runs the final exported inputs on ddc/f92. It remains
separate from public Core compilation, current silicon validation and
production deployment.
