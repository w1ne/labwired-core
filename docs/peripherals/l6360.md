# L6360 digital IO-Link master PHY

The `l6360` kit attaches the documented L6360 control state to an existing I2C
controller, GPIO pads and UART. The register engine is described in
[l6360_control.md](l6360_control.md). It uses DS8900 Rev 9 sections 6–8 and
Tables 5, 12, 16 and 23; it does not replace the shared UART network.

## Connections

```yaml
external_devices:
  - id: port1
    type: l6360
    connection: i2c1
    config:
      address: 96
      uart: uart1
      encq: PC0
      enl: PA6
      reset_n: PB5
      incq: PA9
      outcq: PA10
      irq: PA4
```

The 7-bit address is 0x60–0x67. Configure the address from the actual A0–A2
straps. `ENCQ`, `ENL` and reset are separate real MCU GPIO signals. `INCQ` is
the MCU transmitter pad; `OUTCQ` is the receiver pad. The optional existing
supply-domain configuration gates I2C, GPIO and UART behavior together.
Supply, L+ validity, protection inputs and inversion remain explicit state.

All seven electrical CQ modes are decoded. Only known, opposing digital
levels assert a CQ overload scenario. Unknown input or contention does not
become a guessed logic value. CQ receiver filtering applies to static input;
nonzero debounce rejects byte reception instead of pretending a delay is a
filter. The firmware's zero-debounce COM2 mode is supported by the existing
timed UART. That engine retains start, data, parity, stop, baud, collision and
receiver error behavior.

The L6360 receiver is inactive while `ENCQ` is asserted. The UART must not
create local echo in that state. L6362A receiver behavior is different and its
valid transmitted echo remains supported. The MCU TX pad publishes each bit
of the same timed UART shifter, including TXINV, parity and stop bits. This
keeps static CQ observers and frame delivery consistent without a second
serial engine.

Propagation uses explicit nominal scenarios: 160 ns TX and 100 ns RX from
Table 5 typical values. These are not guaranteed hardware limits. Analog
24 V rail ramps, regulator settling, load current, slew, thermal behavior and
physical cable qualification are outside this digital model.

## Physical firmware integration

The opt-in `world_iolink_physical` test runs one packaged STM32L476 master and
two packaged device images unchanged. It verifies distinct identity fixtures,
two wake-ups, both port state machines entering OPERATE, live DI8 input changes,
and error counters. It uses the existing World star UART network with a 1 us
quantum and peripheral tick interval 1. Set `IOLINK_STATION_FIRMWARE_DIR` to the
package release directory and `IOLINK_STATION_REPORT_DIR` to an evidence output
directory, then run:

```sh
cargo test -p labwired-core --features event-scheduler --test world \
  world_iolink_physical:: -- --ignored --nocapture
```

The fixture hashes are checked before execution. The exact images, source and
build records belong to `examples/industrial/iolink-station`; this test does not
synthesize successful firmware responses or claim physical-board tests.
