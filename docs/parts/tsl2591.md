## Support matrix

| Behavior | Status | Notes |
|----------|--------|-------|
| Command byte 0xA0 | reg | ✅ | pointer_mask 0x1F; auto-increment burst reads |

| Analog / power | ❌ | Bench |

## Stimulus

Host inputs: `ch0`, `ch1` (counts at 1× gain, 100 ms).

## How to run

1. Place the part and an MCU in Playground, or add it to a system YAML:
   ```yaml
   external_devices:
     - id: "tsl2591"
       type: "tsl2591"
       connection: "i2c0"   # the bus id your chip system uses
   ```
2. Agent: `labwired_list` → `labwired_describe id=tsl2591` → wire → `labwired_validate` → `labwired_run` / `labwired_verify`.
3. Register-level smoke: `cargo test -p labwired-core --test everyday_sensor_set` — ID 0x50 via 0xB2; after ENABLE = 0x03 and 100 ms, AVALID set and CH0/CH1 = 1200/300. The same file's negative control proves the check fails against a part that answers only 0x00 or only 0xFF.

## Limitations

- Inputs are raw counts (the datasheet characterises counts, not lux).
- PON-only gating and the CH0→CH1 shadow latch are not modelled.

See the YAML header for the full datasheet trace and every named approximation.
