# STK3800 Renode onboarding smoke

**Result:** booted and smoke-passing in the repository simulator.

- Imported system: `configs/systems/onboarding/stk3800.yaml`
- Renode source map: [STK3800 board](https://github.com/renode/renode/blob/master/platforms/boards/silabs/stk3800.repl) inherits the [EFM32WG995 CPU map](https://github.com/renode/renode/blob/master/platforms/cpus/silabs/efm32xg/efm32wg995.repl): Cortex-M4F, 256 KiB flash at zero, 32 KiB SRAM, UART0 at `0x4000e000`
- Run: 100,000 instructions, stopped at `max_steps`
- Smoke assertions: UART0 emitted `STK3800 EFM32WG995 UART0 smoke`; expected stop reason was `max_steps`

The imported profile retains only execution memory and the modeled UART0 path exercised by this smoke. Its generated GPIO, buttons, I2C, timers, other UARTs, LEUARTs, bit-band, and Python peripheral declarations are omitted and are not covered by this result.

The first attempt used the wrong UART base and faulted on an unmapped write; the full run evidence is retained under [attempt 01](../coverage/renode-onboarding/attempt-history/stk3800/attempt-01/). The descriptor was corrected to Renode's UART0 base before this passing result.

Evidence: [metrics](../coverage/renode-onboarding/metrics/stk3800/onboarding-metrics.json), [simulator result](../coverage/renode-onboarding/metrics/stk3800/simulation-output/result.json), [JUnit assertions](../coverage/renode-onboarding/metrics/stk3800/simulation-output/junit.xml), and [run log](../coverage/renode-onboarding/metrics/stk3800/logs/run_smoke.log).

This is repository CLI simulation evidence, not hardware confirmation or a hosted `labwired_verify` verdict.
