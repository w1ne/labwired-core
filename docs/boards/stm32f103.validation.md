# Imported STM32F103 onboarding smoke

The imported system profile is bounded to a Cortex-M3, 64 KiB flash, 20 KiB
SRAM, RCC, GPIOA, GPIOB, USART2 and I2C1. These windows match the common
STM32F103C8 density. The system connects a modeled TMP102 at I2C address `0x48`.
Other STM32F1 variants and peripherals are outside this profile.

The exact imported-system smoke ran the Cortex-M3 I2C fixture for 50,000,000
instructions. It emitted the `F103 I2C` and `DONE` markers through USART2,
observed `SR1=0x0400` after addressing an absent slave, generated STOP and
observed the bus idle, then read the TMP102 temperature register over I2C1.
The repeated-START read returned `0x1900` (25 °C). The firmware then wrote
`0xFFFF` to the TMP102 configuration register and read back `0xFFF0`, confirming
that the modeled read-only and reserved bits keep their reset values while the
writable bits accept the write. It then wrote `0x3457` to T_LOW and `0x678E` to
T_HIGH, reading back `0x3450` and `0x6788`; D2:D0 remained zero while the alert
threshold fields retained their programmed values. It then sent a one-byte
T_LOW update (`0x22`) followed by STOP and read back `0x2250`, showing the MSB
changed while the existing `0x50` low byte remained. All UART markers and the
bounded `max_steps` stop are required smoke assertions. GPIOA and GPIOB are mapped
because the firmware configures PA2 for USART2 and PB6/PB7 for I2C; GPIO pad
behavior is not asserted. The run assumes an ideal power rail; it does not
exercise power-on or brown-out reset behavior.

Evidence, including the result, UART output, snapshot, JUnit report and build/run
logs, is in
[`docs/coverage/renode-onboarding/metrics/stm32f103/`](../coverage/renode-onboarding/metrics/stm32f103/).

This is a local LabWired CLI smoke against the imported manifest, not a hosted
`labwired_verify` model-verification verdict. It does not validate the whole
STM32F103 platform, the unlisted peripherals, Renode equivalence or physical
hardware.
