# nRF5340 (Nordic dual-core wireless SoC) — application core

The nRF5340 pairs a 128 MHz Cortex-M33 **application core** (1 MB flash,
512 KB RAM) with a 64 MHz Cortex-M33 **network core** for the BLE / 802.15.4
radio. This LabWired profile models the **application core** — the half that
runs user firmware — to the point that unmodified upstream Zephyr boots and
prints over the console.

The defining trait of this profile is its address view. The Zephyr
`nrf5340dk/nrf5340/cpuapp` target is the secure application-core image and uses
peripherals at `0x5000_0000` (DT `peripheral@50000000`), so UARTE0 is
`0x5000_8000`, TWIM1 is `0x5000_9000`, and CLOCK is `0x5000_5000`. The separate
`cpuapp/ns` target uses the `0x4000_0000` non-secure aliases; LabWired does not
silently treat those two firmware profiles as interchangeable.

## What is proven

Unmodified upstream Zephyr v3.7 `samples/hello_world`, built for
`nrf5340dk/nrf5340/cpuapp`, boots end to end and prints
`Hello World! nrf5340dk/nrf5340/cpuapp` over the UARTE0 console. The boot walks
the genuine Zephyr `clock_control` (HFCLK/LFCLK start + status poll),
`nrf_rtc_timer` init (RTC1 on LFCLK), the ARMv8-M MPU setup, and the UARTE0
EasyDMA TX path. The entire run is **bus-violation-free**
(`LABWIRED_TRACE_VIOLATIONS=1`): every address the firmware touches is mapped.
A separate integration test attaches the declarative BMI270 model to TWIM1 and
reads CHIP_ID `0x24` through a real EasyDMA repeated-START transaction. This
proves the board's default I²C controller and the IMU model work together; it
does not prove physical signal timing or TrustZone isolation.

The FICR window serves the vendor SVD register file. Its INFO.PART is N5340,
and its 4-KiB page size × 256-page code size agrees with the chip profile's
1-MiB flash. The SVD leaves per-device IDs, RAM/FLASH variants, and trim values
unspecified; the model preserves those erased values rather than assigning a
specific production device.

GPIOTE0 uses the shared Nordic task/event model at the secure SVD address
`0x5000D000`. The integration gate configures channel 0, triggers
`TASKS_SET0`, and observes the selected bit in the GPIO model's `GPIO0.IN`
input latch. This checks task-to-port readback; external electrical pad routing
is not asserted, and this is not a silicon capture.

The UICR window serves the vendor SVD register file in the unprogrammed state:
every SVD register reads `0xFFFFFFFF` (reserved gaps are not claimed). The SVD gives APPROTECT, SECUREAPPROTECT and
ERASEPROTECT a reset value of 0, which its own enums decode as "Protected";
erased NVM reads all ones, so the chip profile overrides those three. An erased
part therefore decodes as debugger access protected (not `0x50FA50FA`) and
ERASEALL unprotected. Writes store directly; NVMC write-enable gating and
1 → 0 flash semantics are not modelled.

## Not yet modeled

- **Network core** (second Cortex-M33) and the BLE / 802.15.4 **radio**.
- **TrustZone / SPU** access enforcement (the SPU window is a benign stub; the
  secure/non-secure split is not policed). A secure `cpuapp` ELF can run, but
  this is not evidence that an isolation policy or TF-M partition is correct.
- **Analog trims** — the FICR trim table and UICR remain erased, and
  OSCILLATORS/REGULATORS and the trim target remain stubs, so oscillator/radio
  calibration is absent. This is irrelevant to the digital console path but
  means RF/analog fidelity is not represented.
- No live **silicon diff** — there is no nRF5340 bench board, so the models are
  validated against real firmware behaviour, not a register capture.
