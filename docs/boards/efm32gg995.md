# EFM32GG995 Renode onboarding smoke

**Architecture:** ARM Cortex-M3.

## Imported execution profile

`configs/chips/onboarding/efm32gg995.yaml` keeps the imported 1 MiB flash and
128 KiB RAM map and exposes the model-backed USART0 at `0x4000c000`. Other
generated peripherals are omitted because this smoke does not exercise them.

## Current evidence

The exact imported-system smoke in
`examples/renode-onboarding/efm32gg995-smoke.yaml` runs the Cortex-M3 firmware
for 100,000 instructions. It checks that USART0 emits `EFM32G USART0 smoke` and
that execution reaches the configured `max_steps` limit.

Build and simulator logs, UART output, JUnit assertions, result JSON, and a
snapshot are recorded under
[`docs/coverage/renode-onboarding/metrics/efm32gg995/`](../coverage/renode-onboarding/metrics/efm32gg995/).
The full imported inventory is summarized in the
[`Renode onboarding scoreboard`](../coverage/renode-onboarding-scoreboard.md).

This is repository CLI smoke evidence for the Cortex-M3, memory, and USART0
path. It does not establish full EFM32GG995 peripheral coverage, hosted
`labwired_verify` model verification, or hardware confirmation.
