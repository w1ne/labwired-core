# RP2350 (Raspberry Pi Pico 2)

The RP2350 (dual Cortex-M33, 4 MB XIP flash on Pico 2, 520 KB SRAM) is
onboarded as a descriptor-level derivative of the RP2040 lane: it reuses the RP2040
behavioural models for UART (PL011), I2C, SPI, DMA, PIO (v1-compatible on
PIO0–2), SIO, ADC, PWM, timer, and watchdog, with a `profile: rp2350` on the
shared clock/reset model for the moved APB map. It is **smoke-validated, not
hardware-validated** — no Pico 2 has been on the bench.

This page covers the non-wireless **Pico 2 carrier** (user LED GP25) and the
narrow **[Pico 2 W + BME280 example](../../examples/rp2350-pico2w-bme280/README.md)**.
The Pico 2 W profile omits its CYW43439 wireless device and the WL_GPIO0 LED it
drives; it only claims RP2350 I2C0 plus the external sensor. The USB-C castellated
module is **[Waveshare RP2350-Zero](rp2350-zero.md)** (WS2812 on GP16).

The Pico 2 + BME280 profile reads the sensor ID and raw temperature over I2C0
on GP4/GP5. Its committed local simulator evidence is in
[`examples/pico2/evidence/bme280/`](../../examples/pico2/evidence/bme280/).

For Pico 2 build/run instructions, see
[`examples/pico2/README.md`](../../examples/pico2/README.md).
Zero: [`examples/rp2350-zero/README.md`](../../examples/rp2350-zero/README.md).

## Modeled (from chip yaml)

SYSINFO (CHIP_ID reads `0x30005927`; PART not in the datasheet, unverified), CLOCKS/RESETS/XOSC/PLL_SYS/PLL_USB/ROSC
(`rp2350` clkrst profile), UART0/1 (PL011), SPI0/1, I2C0/1, ADC, PWM,
TIMER0, WATCHDOG, DMA, PIO0/1/2 (v1 instruction set), SIO (core 0),
XIP_CTRL (declarative), POWERMAN/TICKS/TBMAN stubs, SysTick, NVIC.
Boot ROM API window at 0x00000000 (clean-room, `crates/core/roms/rp2350/`:
`rom_table_lookup` at the well-known 0x16 pointer, bootrom_state_reset,
get_sys_info CHIP_INFO, reboot NORMAL, the XIP-state no-ops,
flash_devinfo16_ptr), BOOTRAM (1 KB + WRITE_ONCE + BOOTLOCK0..7), USBCTRL
(RP2040 controller model on USBCTRL_IRQ 14; arduino-pico's TinyUSB CDC
enumerates against the simulated host and its `Serial` output is what the
Arduino matrix captures).
Double-precision coprocessor (DCP, p4/p5, datasheet 3.6.2): a sequence-level
model of the pico-sdk canned instruction sequences
(`crates/core/src/cpu/cortex_m/rp2350_dcp.rs`) — double/float add, sub,
mul, div, sqrt, compares and int/float/double conversions give IEEE-754
round-to-nearest-even results with denormals flushed to zero; engaged flag
and state save/restore follow the SDK's saving wrapper. `ddiv_fast` /
`sqrt_fast` return the correctly rounded value (silicon: < 0.5 ulp before
rounding); NaN results are the default NaN; RXVD (dclassify) faults.
GPIO coprocessor (GPIOC, p0, datasheet 3.6.1): every `gpio_coproc.h`
encoding runs as the equivalent SIO GPIO access
(`crates/core/src/cpu/cortex_m/rp2350_gpioc.rs`); pico-sdk `gpio_put` /
`gpio_set_dir`, and so arduino-pico `pinMode`/`digitalWrite`, use it.
TIMER0 and SIO use their RP2350 register maps (`profile: rp2350`): TIMER
INTR/INTE/INTF/INTS sit at 0x3c–0x48 behind LOCKED/SOURCE (storage only),
and every SIO GPIO register has a HI twin at +4 (only GPIO 0..29 modelled;
HI registers read 0).
SCS ACTLR (0xE000E008) as a plain register. SYSINFO at the RP2350 offsets
(PACKAGE_SEL 0x04 = QFN60, PLATFORM 0x08 = ASIC).

## Explicitly not modeled

TrustZone / security partitions, second M33 core and SIO FIFO dual-core
bring-up, Hazard3 RISC-V cores, the real bootrom boot path (IMAGE_DEF scan,
XIP setup) and every ROM API not listed above (flash erase/program, OTP,
partition tables), the redundancy coprocessor (p7), TIMER1, HSTX/DVI, PIO v2-only instructions, OTP, SHA-256,
TRNG, QMI programming. Sim86 claims several of these; we declare nothing
we do not model.
