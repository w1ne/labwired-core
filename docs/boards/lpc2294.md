# LPC2294 validation status

## Current status

The imported LPC2294 descriptor was measured against its exact imported system
with a direct ARMv4T integer-loop ELF loaded at the declared flash base,
`0x08000000`. LabWired rejected the declared `arm7tdmi-s` core before executing
any instructions:

```text
chip 'lpc2294': unsupported ARM classic core 'arm7tdmi-s'; no native adapter is available
```

The scoreboard records `run_attempted: true`, `booted: false`,
`smoke_passed: false`, and zero instructions with a `config_error` stop reason.
The run log, result JSON, JUnit report, snapshot, and stage logs are under
[`docs/coverage/renode-onboarding/metrics/lpc2294/`](../coverage/renode-onboarding/metrics/lpc2294/).

The current inventory has **245 descriptors; 172 runs attempted; 170 booted;
170 booted and smoke-passing; 73 `not_run`; 2 run failures; 0 unmeasured**.
The failures are LPC2294 ARM7 and Cortex-R52. A smoke pass proves only its
script assertions, not full peripheral coverage.

The imported descriptor identifies an ARM7TDMI-S / ARMv4T target. LabWired has
no ARM7 CPU implementation. `arch: arm` alone does not make this an ARM7
machine: the current ARM builder only accepts a `cortex-m*` core here, and
rejects `arm7tdmi-s`.

## Bounded descriptor

The chip profile names `core: arm7tdmi-s` and retains only the two imported
UART windows backed by the engine's generic `ns16550` model. It omits the four
`lpc_can` windows because they resolve to zero-answering stubs, and omits
`lpc_ctimer` because the engine has no registered model for it. The profile is
not marked verified; the UART mappings have not been exercised on this target.
The imported flash and RAM ranges also remain unverified.

The earlier generated positive report loaded a Thumb Cortex-M fixture and
faulted on a memory access at `0x2001ffe0` after two instructions. It was not
ARM7 evidence and is excluded from the scoreboard.

## Next work

A real ARM7TDMI/ARMv4T adapter is required before the LPC2294 can boot in
LabWired. No CPU or peripheral stub was added. The profile names
`core: arm7tdmi-s` and retains the two imported UART windows backed by the
generic `ns16550` model. It omits the four zero-answering `lpc_can` windows and
the unmodeled `lpc_ctimer`. The UART mappings and memory ranges remain
unverified because the CPU did not boot. The whole-platform descriptor remains
`verified: false`.
