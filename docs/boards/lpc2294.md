# LPC2294 validation status

## Current measurement (2026-11-09)

The imported LPC2294 system booted the ARM7TDMI-S fixture for **100,000
instructions** and passed **3/3 smoke assertions**. The firmware runs nine
checks and prints one letter per check; the UART capture is
`LPC2294 checks PPPPPPPPP DONE` on UART0 and `LPC2294_UART1_OK` on UART1. The
result, UART capture, JUnit assertions, snapshot and build/run logs are under
[`docs/coverage/renode-onboarding/metrics/lpc2294/`](../coverage/renode-onboarding/metrics/lpc2294/).

Checks (source: `examples/renode-onboarding/lpc2294-arm7-uart-smoke.S`):

1. SCB: PLLCFG, PLLCON and the feed writes; PLLSTAT.PLOCK (bit 10) set;
   VPBDIV, MAMTIM and PLLCFG read back.
2. PINSEL0 reads back the UART0/UART1 pin selection.
3. UART0 divisor latches behind LCR.DLAB read back; LCR reads 0x03 after.
4. UART0 LSR reads THRE|TEMT while idle. Every transmitted byte waits for
   LSR.THRE.
5. Port 1 IOSET/IOCLR/IODIR on P1.16-P1.23: latch and IOPIN agree.
6. Ports 0-3 keep separate output latches.
7. IOCLR reads 0; an input pin (IODIR 0) does not show its latch in IOPIN.
8. UART1 divisor read back and LSR idle, then a line on UART1.
9. PL190 slot 0 handles a software IRQ on source 5: the ARM7 enters the IRQ
   vector, reads `VICVectAddr`, reaches the configured handler, clears the
   software source, writes EOI, and returns with `VICIRQSTATUS` clear.

## Memory map fix

The import placed flash at 0x08000000 and RAM at 0x20000000 (the STM32
default). The LPC2294 has 256 KiB flash at 0x0 and 16 KiB SRAM at 0x40000000
(RTEMS `bsps/arm/rtl22xx/start/linkcmds`). The earlier smoke passed only
because its firmware was linked at 0x08000000 too. Renode
`platforms/cpus/lpc2294.repl` maps one 64 KiB `internal_sram` at both 0x0 and
0x40000000; that is a Renode shortcut, not the silicon map.

## Claimed peripherals

Register addresses come from RTEMS `bsps/arm/rtl22xx/include/lpc22xx.h`.

| id | model | scope |
|---|---|---|
| `vic` | `arm_pl190_vic` | IRQ/FIQ status, IRQ/FIQ selection, enable set/clear, software IRQ set/clear, 16 vectored slots, acknowledge/EOI, and Renode PL190 peripheral IDs. CPU IRQ/FIQ outputs are connected. Peripheral IRQ input wiring is not claimed. |
| `uart0`, `uart1` | `uart`, `dw_apb_uart` layout (16550 at a 4-byte stride) | Polled TX, LSR, LCR/DLAB divisor latches. No interrupts. |
| `port0`..`port3` | `gpio`, `lpc2xxx` layout | IOPIN/IOSET/IODIR/IOCLR. |
| `pinsel` | declarative storage | PINSEL0/1/2; the function mux is not routed. |
| `scb` | declarative storage | MAMCR, MAMTIM, MEMMAP, PLLCON, PLLCFG, PLLSTAT, PLLFEED, PCONP, VPBDIV. |

Not modelled, and stated in the descriptor:

- IOPIN writes are ignored. The PINSEL mux does not route pins. Pull
  resistors are not modelled; an undriven input reads 0.
- PLLSTAT reads PLOCK = 1 at all times and does not mirror PLLCFG/PLLCON.
  The PLL, VPB divider and MAM do not change timing. MEMMAP does not remap
  vectors.
- Reset values of PINSEL1, PINSEL2 and the SCB registers (other than
  PLLSTAT) are 0 here. They were not checked against UM10114: the NXP PDF
  was not retrievable this round.

Not declared (no model in this engine): timers 0/1, CAN1-4, I2C, SPI, ADC,
RTC, watchdog, PWM, the external memory controller (BCFG) and external memory
windows. The VIC's external source pins are not connected to peripheral models.
