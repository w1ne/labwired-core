# EFM32GG942 Renode onboarding smoke

**Architecture:** ARM Cortex-M3.

## Imported execution profile

`configs/chips/onboarding/efm32gg942.yaml` retains the imported 1 MiB flash and
128 KiB RAM map and the model-backed USART0 at `0x4000c000`. The other entries
from the generated peripheral inventory were omitted because they are not part
of this measured execution profile.

## Current evidence

The exact imported-system smoke in
`examples/renode-onboarding/efm32gg942-smoke.yaml` executed 100,000 Cortex-M3
instructions from the imported flash mapping. It passed both configured
assertions: USART0 output contained `EFM32G USART0 smoke`, and the run stopped
at the configured `max_steps` limit.

Build and simulator logs, UART output, JUnit assertions, result JSON, and a
snapshot are recorded under
[`docs/coverage/renode-onboarding/metrics/efm32gg942/`](../coverage/renode-onboarding/metrics/efm32gg942/).
The full imported inventory is summarized in the
[`Renode onboarding scoreboard`](../coverage/renode-onboarding-scoreboard.md).

This is repository CLI smoke evidence for the Cortex-M3, memory, and USART0
path. It does not establish full EFM32GG942 peripheral coverage, hosted
`labwired_verify` model verification, or hardware confirmation.
