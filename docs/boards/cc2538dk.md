# CC2538DK

The **TI CC2538DK** with a **CC2538SF53** (Cortex-M3, 32 MHz max, 2.4-GHz
IEEE 802.15.4 radio): 512 KiB of flash at `0x0020_0000` (the boot ROM, not
flash, sits at `0x0`), 32 KiB of SRAM at `0x2000_0000`, four active-high LEDs
on the SmartRF06 EB (`PC0`–`PC3`), five active-low keys (`PA3`, `PC4`–`PC7`)
and the console on **UART0** `PA0`/`PA1` through the I/O controller.

This is the **UART+LED L1 slice**. Boot, the SYS_CTRL reset clock, the UART0
console and the address-masked GPIO LED path (with `GPIO_DATA` read-back) are
proven by a committed smoke fixture and an `io-smoke.yaml`.

!!! warning "Not claimed yet"
    SYS_CTRL clock gating has no effect on other blocks, the IOC pin mux and
    pad overrides are a stub, and GPIO interrupts are not raised. The RF core,
    AES/PKA, flash controller, SSI, I²C, GPTimers, USB, uDMA, WDT/sleep timer
    and SoC ADC are declared stubs. The boot ROM is not present. There is no
    silicon capture: **SIM-DERIVED**.

## Memory map and board wiring

| Region / signal | Base / pin | State |
|--------|------|-------|
| ROM | `0x0000_0000` | not modelled — fast boot enters the flash vector table |
| Flash | `0x0020_0000`, 512 KiB | modelled — the smoke links and runs here; CCA at `0x0027_FFD4` |
| SRAM | `0x2000_0000`, 32 KiB (upper 16 KiB retained in PM2/3) | modelled — stack at the top |
| SYS_CTRL | `0x400D_2000` | modelled (`cc2538_sys_ctrl`) — CLOCK_CTRL/CLOCK_STA, gate banks (storage only) |
| IOC | `0x400D_4000` | `type: stub` — pin mux / pad overrides not modelled |
| UART0 (console) | `0x4000_C000` | modelled — PL011-compatible, IRQ 5 |
| UART1 | `0x4000_D000` | modelled — same layout, unexercised |
| GPIO A–D | `0x400D_9000` + `0x1000`×n | modelled (`cc2538_pl061_gpio`) — masked DATA, DIR, AFSEL |
| LEDs | LED1 PC0 (red, not driven — USB pull-up), LED2 PC1, LED3 PC2, LED4 PC3 | modelled GPIO — active high |
| Keys | SELECT PA3, LEFT PC4, RIGHT PC5, UP PC6, DOWN PC7 | modelled GPIO input — active low, reset pull-up |
| UART0 VCP | PA0 (RX) / PA1 (TX) | simulator captures the UART0 stream; the USB debugger bridge is not modelled |
| RF core / AES / PKA / flash ctrl / SSI / I²C / GPTimers / USB / uDMA / WDT / ADC | see descriptor | `type: stub` |

## Boot path

**Fast boot.** The engine loads the ELF and enters it at its vector table
(`0x0020_0000`) with SP seeded from the firmware's vector table
(`0x2000_8000`). On silicon the ROM reads the Customer Configuration Area and
does the same for a valid image (SWRU319C §8.6.1); the committed firmware
carries a real CCA so it would. The ROM itself is not modelled.
