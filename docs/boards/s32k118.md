# NXP S32K118 imported profile

## Measured profile

LabWired's onboarding profile for the imported Renode `s32k118` target is
narrowed to what the engine executes and the smoke exercises. It follows
Renode's
[`s32k118.repl`](https://github.com/renode/renode/blob/master/platforms/cpus/s32k118.repl):

- **CPU:** Cortex-M0+ (ARMv6-M) at 48 MHz, the part's maximum core clock.
- **Memory:** 256 KiB program flash at `0x00000000` and the 0x5800-byte upper
  SRAM at `0x20000000`. The original import placed flash at `0x08000000` (an
  STM32 default); that is corrected. FlexNVM, FlexRAM and the lower SRAM are
  omitted.
- **LPUART0** at `0x4006A000` (Renode `NXP_LPUART`). This uses the i.MX RT
  LPUART model: VERID/PARAM/GLOBAL/PINCFG ahead of BAUD/STAT/CTRL/DATA
  (`0x10..0x1C`), VERID `0x04010003`, 4-entry FIFOs (PARAM `0x0202`), and
  per-frame TX timing from BAUD (OSR/SBR) and a 48 MHz LPUART clock. Polled TX
  only: no IRQ is declared, and DMA, RX timing and LIN are not claimed.
- **GPIO PTA..PTE** data blocks at `0x400FF000 + n*0x40` (Renode
  `NXPGPIOPort` "gpio" region): PDOR/PSOR/PCOR/PTOR/PDIR/PDDR on the Kinetis
  GPIO model. PIDR is not modelled.

Not modelled and omitted from the descriptor: PCC clock gating (Renode also
tags `PCC_LPUART0` as a constant, so neither enforces the gate), the PORT
pin-mux and pin-interrupt blocks at `0x40049000..`, SCG, LPUART1, LPSPI0/1,
LPIT, LPTMR, FlexCAN, FTM and the DWT.

The earlier report on this page described a 2026-10-18 run of a Thumb-2
Cortex-M3 fixture (`uart-ok-thumbv7m.elf`) against the unnarrowed import, and
listed zero-answering stubs as hardware coverage. That run never exercised an
S32K118 peripheral and is withdrawn.

## Smoke evidence

The firmware crate `crates/firmware-s32k118-smoke` (`thumbv6m-none-eabi`)
programs LPUART0 for 8N1 at OSR=15/SBR=26 (115,384 Bd from 48 MHz), sets
`CTRL.TE`, and polls `STAT.TDRE` before each byte. It prints a banner and
the VERID/PARAM/BAUD/CTRL readbacks and a MULS result. It then drives PTD0
and PTD3 through PDDR/PSOR/PCOR/PTOR and reads each step back through PDOR.
Before the final report it waits for `STAT.TC`, then toggles PTD0 as a
heartbeat. Because PCC and PORT are not modelled, it skips `PCC_LPUART0` and
`PORTD_PCR0`; silicon firmware must program both.

It ran **2,000,000 instructions** and passed 6/6 checks: the UART banner and
the ordered readback lines (`verid=04010003 param=00000202 baud=0f00001a
ctrl=00080000`, `ptd pddr=00000009 set=00000001 clr=00000000 tog=00000009`,
`pass=0f`), at least 3 PTD0 edges, the MULS word at `0x20000000` and the pass
word `0x5118000F` at `0x20000004`, and `max_steps`.

With LPUART0 removed from the descriptor, the same firmware faults on its first
LPUART0 access and passes 2/6
(`docs/coverage/renode-onboarding/attempt-history/s32k118/2026-11-08-lpuart0-negative-control/`).
The first attempt without a declared `cpu_hz` timed the LPUART against the
600 MHz i.MX RT default clock and fit only 38 characters into the step budget;
it is preserved in
`attempt-history/s32k118/2026-11-08-lpuart-default-600mhz-timebase/`.

The exact system manifest is `configs/systems/onboarding/s32k118.yaml` and the
smoke script is `examples/renode-onboarding/s32k118-smoke.yaml`. Per-target
metrics, JUnit, UART output, simulator result, snapshot and logs are under
`docs/coverage/renode-onboarding/metrics/s32k118/`.

This is local CLI simulation evidence for the smoke assertions. It does not
show whole-SoC coverage, Renode equivalence or hardware behaviour. See the
[generated scoreboard](../coverage/renode-onboarding-scoreboard.md) for the
current global totals.
