# UT32M0R500 validation status

## Current measurement (2026-11-09)

Cortex-M0+ for **200,000 instructions** and passed **7/7 smoke assertions**.
The firmware runs twelve register and interrupt checks and prints one letter
per check; the UART0 capture is `UT32 checks PPPPPPPPPPPP DONE`, and the
summary word at 0x20017F00 is 0x5E320FFF. UART1 prints one line. GPIO 45
(GPIO2 pin 13) shows at least 6 edges. A stimulated rising edge on that pin
asserts combined GPIO IRQ 24 in NVIC; clearing `INTSTATUS` drops the
level-pended NVIC bit. The timer check exercises channel 1 of timer0 and
channel 2 of timer1: each counts down, asserts RIS/MIS, and clears its
interrupt latch. The result,
UART capture, JUnit assertions, snapshot and build/run logs are under
[`docs/coverage/renode-onboarding/metrics/ut32m0r500/`](../coverage/renode-onboarding/metrics/ut32m0r500/).

Checks (source: `crates/firmware-ut32m0r500-smoke/src/main.rs`):

1. GPIO0 OUTEN, ALTFUNC and INTEN read 0 after reset.
2. GPIO2 ALTFUNC resets to 0xFFFF; ALTFUNCCLR frees pin 13.
3. GPIO0 pin 3 with PULL_ENABLE and PULL_UP_DOWN = 1 reads 1.
4. The same pin with PULL_UP_DOWN = 0 reads 0.
5. GPIO1 pins 0..3: OUTENSET, DATAOUT 0x5, DATA reads the pads.
6. MASKLOWBYTE[0x0C] = 0x08 changes pins 2 and 3 only.
7. GPIO1 pin 9 set and cleared through MASKHIGHBYTE[0x02].
8. OUTENCLR releases pin 0; DATA reads its pull-down.
9. GPIO1 pin 1 rising-edge INTSTATUS latches; a write of 1 clears it.
10. A pattern at the top of the 96 KiB SRAM reads back.
11. SP804 timer0 channel 1 and timer1 channel 2 count down, assert RIS/MIS,
    and clear their interrupt latches.
12. A stimulated rising edge on GPIO2 pin 13 latches `INTSTATUS`, asserts
    NVIC IRQ 24, then deasserts the line and clears its NVIC pending bit when
    `INTSTATUS` is cleared.

## Declared surface

Sources: Renode `platforms/cpus/ut32m0r500.repl` (memory map, instance
bases, timer clock/IRQ routes, GPIO2 `alternateFunctionResetValue`), Renode
`ARM_AHB_GPIO.cs` (register map), Renode `ARM_SP804_Timer.cs`, Arm DDI 0271D
(SP804 register/timing behavior), and the Frontgrade (Cobham CAES) application note
"UT32M0R500 Enable the GPIO" (12/21/2017: bank addresses, interrupt type
and polarity table, masked byte access, pull-up through
`PinPullEnable` + `PinPullDirection`).

| Block | Base | Model |
|---|---|---|
| flash 64 KiB | 0x01000000 | memory |
| SRAM 96 KiB | 0x20000000 | memory |
| uart0 / uart1 | 0x40004000 / 0x40005000 (4 KiB each) | `gaislerapbuart` profile `gaisler`, polled |
| gpio_bank0..2 | 0x40020000 / 0x40021000 / 0x40022000 (4 KiB each) | `gpio` profile `cmsdk`; combined IRQs 22 and 24 on banks 0 and 2; bank 2 `reset_altfunc: 0xFFFF` |
| timer0 / timer1 | 0x40001000 / 0x40002000 (4 KiB each), IRQ 1 / 2 | `arm_sp804_timer`; two counters per instance |

GPIO number `16 * bank + n` is bank pin n (the app note's GPIO 45 is GPIO2
pin 13). The banks are not named `gpio0..2`, because those names turn on
the Nordic GPIOTE pass in the bus.

Two deviations from Renode, both toward the hardware documents: DATA reads
the pad level on output pins too (Renode returns 0 there; the Arm CMSDK
GPIO samples the pin), and the MASKLOWBYTE/MASKHIGHBYTE arrays are modelled
(Renode tags them; app note §3.5.2 describes them). A level-type interrupt
latches when a pad changes, as in Renode. Combined IRQ is `INTSTATUS &
INTEN`; the smoke checks the GPIO2 combined output through NVIC. GPIO1's
optional dedicated per-pin IRQ outputs (NVIC 5..12) are not declared or
claimed.

The SP804 implementation follows Arm DDI 0271D. This smoke checks timeout
status and interrupt-latch clearing on one channel in each instance; it does
not check every counter mode, prescaler, or exception delivery path.

Not modelled on the declared blocks: GPIO1's optional dedicated per-pin IRQ
outputs, alternate-function pad routing (an ALTFUNC pad reports AF and this port
does not drive it), open-drain output, SOFTRESET behaviour (the bit is
stored), and the PID/CID words.

Not declared (no model in this engine): boot ROM, EDAC SRAM, system ROM,
MTB, CAES ADC, CAN0/1, and the
Renode Tag-only blocks (RTC, PWM, SPI, DACs, watchdog, I2C0/1, trim
control, NFC, comparators, system controller).
