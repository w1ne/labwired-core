# ESP32-P4 / Guition JC4880P443

Espressif **ESP32-P4** on the **Guition JC4880P443** module (4.3" 480x800 MIPI-DSI touch panel, 16 MB PSRAM, 32 MB flash, LVGL) — single HP core **RISC-V RV32IMAFC**, 768 KB HP SRAM, 128 KB mask ROM, 32 KB LP SRAM, external SPI flash + PSRAM. LabWired's P4 target runs a bare-metal ELF whose console reaches the capture sink on UART0.

This is an **L1 (smoke)** target: the UART0 console path is a real engine (the shared Espressif UART twin, paced at the P4's 360 MHz), proven by the committed `esp32p4-demo` fixture. The P4 GPIO (a two-bank block, not the C3/C6 head), IO_MUX, HP_SYS_CLKRST and the interrupt matrix are SVD-derived declarative register files with no behavioural engine, and the MIPI-DSI panel, GDMA/DMA2D, USB, H.264/JPEG/ISP and the LP subsystem are **not modelled**. No silicon capture exists: register behaviour is SIM-DERIVED.

!!! warning "Not the dual-architecture part"
    The P4 silicon carries an LX7-class low-power core *in addition to* the HP
    RISC-V core. The engine's P4 descriptor models the **HP core only** — exactly
    the scope `esp32c6.yaml` takes for its own LP core. The official
    `esp32p4.svd` declares the CPU as `RV32IMAFC`; the F and A extensions are not
    decoded by the interpreter, so the L1 image links the `riscv32imc` subset.

## Memory map

| Region | Base | Size | Notes |
|--------|------|------|-------|
| XIP / external memory | `0x4000_0000` | 64 MiB window | `SOC_IROM_LOW = SOC_DROM_LOW = 0x40000000`, `SOC_IROM_HIGH = 0x44000000`. Plain memory at L1 — a bare ELF loads at its link addresses. |
| HP SRAM | `0x4FF0_0000` | 768 KB | `SOC_IRAM_LOW/HIGH = 0x4ff00000/0x4ffc0000`. The mask ROM keeps `0x4FF4_0000`..`0x4FFC_0000`; the app stack is seeded at `0x4FF4_0000`. |
| Mask ROM (HP) | `0x4FC0_0000` | 128 KB | Optional, loadable via `LABWIRED_ESP32P4_ROM`; stays zero without it. |
| LP SRAM | `0x5010_8000` | 32 KB | Mapped so RTC/LP code does not fault; the LP core is not modelled. |
| PSRAM (external) | `0x4800_0000` | 16 MiB | `SOC_EXTRAM_LOW/HIGH`. Plain window — no MSPI/DDR PHY behind it at L1. |
| Flash | — | 32 MiB | The JC4880P443 module's SPI flash; declared as the XIP window's geometry. |

## Peripherals modelled at L1

| Peripheral | Base | Served by |
|------------|------|-----------|
| UART0/1/2 | `0x500C_A000` / `B000` / `C000` | shared `EspUart` twin (UART0 = console, echoes to stdout) |
| SYSTIMER | `0x500E_2000` | shared `Systimer` (S3/C3 layout) |
| TIMG0 / TIMG1 | `0x500C_2000` / `3000` | shared `esp32::timg::Timg` (MWDT path NOT armed) |
| GPIO | `0x500E_0000` | SVD-derived declarative register file (two-bank; no engine) |
| IO_MUX | `0x500E_1000` | declarative (pad routing recorded, not enforced) |
| HP_SYS_CLKRST | `0x500E_6000` | declarative (no `clock:` gate — the clock tree is not modelled) |
| INTERRUPT_CORE0 | `0x500D_6000` | declarative (matrix source map; not routed through the bus) |

## The MIPI-DSI panel is NOT modelled

The JC4880P443's 4.3" 480x800 MIPI-DSI panel and its capacitive touch controller
have **no engine model**. The engine's display primitive
(`crates/core/src/peripherals/components/declarative_display.rs`) supports
`gpio`, `i2c`, `spi`, `uart`, `analog` and `robotics` transports only — there is
no MIPI-DSI host controller or DSI panel path in `crates/core/src/peripherals/`.
Until a DSI controller model exists, the panel cannot be declared as modelled and
the module must not be added to the catalog as a paintable target. See
`KNOWN_LIMITATIONS.md` for the exact gap.
