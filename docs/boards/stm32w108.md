# STMicroelectronics STM32W108 imported profile

## Measured profile

LabWired's onboarding profile for the imported Renode `stm32w108` target is
narrowed to what the engine executes and the smoke exercises. It follows
Renode's
[`cpus/stm32w108.repl`](https://github.com/renode/renode/blob/master/platforms/cpus/stm32w108.repl):

- **CPU:** Cortex-M3 (ARMv7-M).
- **Memory:** 256 KiB flash at `0x08000000` and 1 MiB SRAM at `0x20000000`
  (Renode's sizes). The flash alias at `0x0`, the FIB at `0x08040000` and the
  external RAM at `0x68000000` are omitted.
- **SC1** at `0x4000C800` (Renode `UART.STM32W_UART`, `+0x100`) in UART mode,
  on the vendor-neutral custom UART map with the STM32W108 offsets:
  `SC1_DATA` at `+0x3C` (TX/RX), `SC1_UARTSTAT` at `+0x48` reading
  `SC_UARTTXFREE` (bit 2) | `SC_UARTTXIDLE` (bit 6) when idle and
  `SC_UARTRXVAL` (bit 1) while a byte is queued, and `SC1_MODE` at `+0x54`
  gating TX until `SC_MODE` = UART. `SC1_UARTCFG`/`UARTPER`/`UARTFRAC` writes
  are accepted but not stored (they read 0), so baud and framing are not
  claimed. Polled only: `INT_SC1FLAG`/`INT_SC1CFG` (`0x4000A808`) are not
  mapped and no IRQ is declared.
- **TIM1/TIM2** at `0x4000E000` / `0x4000F000` (Renode `STM32_Timer`), on the
  generic STM32 timer counter path (CR1/EGR/CNT/PSC/ARR, 16-bit). The
  update/compare flags and interrupt enables live in the separate `INT_TIMx`
  block at `0x4000A800`, which is not mapped, so no timer IRQ is claimed.

Not modelled and omitted from the descriptor: the Ember radio and its
encryptor, the calibration ADC (a Python peripheral in Renode), SC2, and the
`CLK_PERIOD` tag. Renode maps no GPIO block for this part, so none is claimed
here either.

Renode's `STM32W_UART` returns 0 for every read except `SC1_DATA`, so firmware
that polls `SC1_UARTSTAT` would spin forever there. LabWired reports the
reference-manual idle bits instead. This is a deliberate difference from
Renode.

The earlier report on this page described a 2026-10-18 run of a generic
`uart-ok-thumbv7m.elf` fixture that only showed the CPU stepping. It never
touched an STM32W108 peripheral and is withdrawn.

## Smoke evidence

The firmware crate `crates/firmware-stm32w108-boot-smoke`
(`thumbv7m-none-eabi`) writes `SC1_MODE` = 1 (UART), `SC1_UARTCFG` and
`SC1_UARTPER`, stores the idle `SC1_UARTSTAT`, prints `STM32W108 SC1 SMOKE`
polled on `SC_UARTTXFREE`, and waits for `SC_UARTTXIDLE`. Then it runs the
timer checks: reset values, stopped hold, CEN count, PSC=7 ratio, ARR=99
bound and wrap, and CEN-clear freeze. The firmware does not program GPIO
alternate functions or the clock tree. Firmware for real silicon must program
both.

It ran **100,000 instructions** and passed 4/4 checks: the result word
`0x571001FF` (magic | nine check bits) at `0x20080000`, the `SC1_UARTSTAT`
readback `0x44` at `0x2008000C`, the UART banner, and `max_steps`.

With SC1 removed from the descriptor, the same firmware takes a precise
BusFault (BFAR `0x4000C854`) on its first SC1 access and passes 1/4
(`docs/coverage/renode-onboarding/attempt-history/stm32w108/2026-11-08-sc1-negative-control/`).

The exact system manifest is `configs/systems/onboarding/stm32w108.yaml`
and the smoke script is `examples/renode-onboarding/stm32w108-boot-smoke.yaml`.
Per-target metrics, JUnit, UART output, simulator result, snapshot and logs are
under `docs/coverage/renode-onboarding/metrics/stm32w108/`.

This is local CLI simulation evidence for the smoke assertions. It does not
show whole-SoC coverage, Renode equivalence or hardware behaviour. See the
[generated scoreboard](../coverage/renode-onboarding-scoreboard.md) for the
current global totals.
