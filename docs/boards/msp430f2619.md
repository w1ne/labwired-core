# MSP430F2619 onboarding scope

**Status: boots and passes its smoke on the MSP430X core.** SIM-DERIVED: no
MSP430F2619 bench part was measured. The evidence is the committed run under
`docs/coverage/renode-onboarding/metrics/msp430f2619/`.

The same core and module set also run the imported `mspsim-msp430f149`,
`mspsim-msp430f1611` (16-bit CPU, x1xx USART) and `mspsim-msp430f2617` (CPUX,
x2xx USCI_A) descriptors. `mspsim-msp430f5437` stays `not_run`: the x5xx
modules (SFR block at 0x0100, PMM, UCS, USCI_A at 0x05C0, WDT_A, MPY32) have
no models.

## CPU

`arch: msp430`, `core: msp430x` selects the 20-bit CPUX in
`crates/core/src/cpu/msp430.rs`. It implements the 27 core instructions, all
addressing modes, both constant generators, the extension word, the address
instructions, `PUSHM`/`POPM`, `CALLA`, the multi-bit register shifts, the
20-bit interrupt frame, and `SR.CPUOFF` with interrupt wake-up.

The core is compared register-for-register with the GDB `msp430-elf`
simulator on compiler-built programs
(`crates/core/tests/vendor/msp430_gdb_sim_lockstep.rs`, fixtures in
`tests/fixtures/msp430/`).

Limits: every instruction takes one clock cycle (silicon takes 1 to 6 MCLK
cycles). The oscillator-fault and access-violation NMI sources are not
modelled. An unmapped access is a simulation error.

## Memory map

| Region | Address | Size | Model |
|---|---:|---:|---|
| SFRs | `0x0000` | 8 B | `msp430_sfr` |
| RAM mirror | `0x0200` | 2 KiB | alias of the first 2 KiB of RAM |
| Information memory | `0x1000` | 256 B | reads erased (`0xFF`); no factory DCO calibration constants |
| RAM | `0x1100` | 4 KiB | memory |
| Flash | `0x2100` | 122,624 B | memory; vectors at `0xFFC0`-`0xFFFF` |

## Modules

| Module | Address | Type | Modelled | Limits |
|---|---:|---|---|---|
| IE1/IE2/IFG1/IFG2/ME1/ME2/UC1IE/UC1IFG | `0x0000` | `msp430_sfr` | flags and enables are the interrupt request lines | bits with no mapped line are storage |
| BCSCTL3 | `0x0053` | `msp430_bcsctl3` | storage with reset value | no clock rate follows it |
| DCOCTL/BCSCTL1/BCSCTL2 | `0x0056` | `msp430_bcm_plus` | storage with reset values | no clock rate follows it |
| USCI_A0 | `0x005D` | `msp430_usci_a` | UART mode, receive flag and interrupt, `UCLISTEN` loopback | transmit is immediate; no receive errors; SPI, IrDA and auto-baud are storage |
| USCI_A1 | `0x00CD` | `msp430_usci_a` | same as USCI_A0, flags in UC1IFG | same |
| WDTCTL | `0x0120` | `msp430_wdt` | password check; a key violation sets WDTIFG and requests a PUC | the counter does not run |
| Hardware multiplier | `0x0130` | `msp430_mpy` | MPY, MPYS, MAC, MACS, RESLO, RESHI, SUMEXT | none known |

Not modelled and not mapped (an access is a bus error): the bootstrap loader
ROM at `0x0C00`, digital I/O ports, Timer_A, Timer_B, USCI_B0/B1, ADC12,
DAC12, DMA, SVS, Comparator_A+, and the flash controller.

## Smoke

`examples/renode-onboarding/msp430f2619-uart-smoke.yaml` runs
`tests/fixtures/msp430f2619-uart-smoke.elf` (source
`examples/renode-onboarding/msp430-uart-smoke.c`, built with TI msp430-gcc
9.3.1.11 `-mlarge` by `scripts/build_msp430_uart_smoke.sh`). The firmware
prints one letter per check on USCI_A0:

1. hardware multiplier through compiler-generated code
2. MPYS sign extension and MAC carry
3. 32-bit division and remainder
4. OFIFG set after power-on, cleared by firmware
5. polled UART loopback
6. receive interrupt in loopback
7. LPM0 wake-up by the receive interrupt
8. a host byte through the receive interrupt
9. a call into flash above 64 KiB and a data read there

Then it prints one line on USCI_A1 and writes WDTCTL without the password.
The restarted firmware finds WDTIFG set and reports it.

The smoke does not exercise the clock registers, the information memory, the
NMI path, or the transmit interrupt.
