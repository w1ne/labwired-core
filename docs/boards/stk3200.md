# STK3200 Renode onboarding smoke

**Result:** booted and smoke-passing in the repository simulator.

- Imported system: `configs/systems/onboarding/stk3200.yaml`
- Renode source map: [STK3200 board](https://github.com/renode/renode/blob/master/platforms/boards/silabs/stk3200.repl) inherits the [EFM32ZG222 CPU map](https://github.com/renode/renode/blob/master/platforms/cpus/silabs/efm32xg/efm32zg222.repl): Cortex-M0+, 32 KiB flash at zero, 4 KiB SRAM, USART1 at `0x4000c400`
- Run: 100,000 instructions, stopped at `max_steps`
- Smoke assertions: USART1 emitted `STK3200 EFM32ZG222 USART1 smoke`; expected stop reason was `max_steps`

The imported profile retains only execution memory and the modeled USART1 path exercised by this smoke. Its generated GPIO, buttons, I2C, timers, LEUART, bit-band, and Python peripheral declarations are omitted and are not covered by this result.

Evidence: [metrics](../coverage/renode-onboarding/metrics/stk3200/onboarding-metrics.json), [simulator result](../coverage/renode-onboarding/metrics/stk3200/simulation-output/result.json), [JUnit assertions](../coverage/renode-onboarding/metrics/stk3200/simulation-output/junit.xml), and [run log](../coverage/renode-onboarding/metrics/stk3200/logs/run_smoke.log).

This is repository CLI simulation evidence, not hardware confirmation or a hosted `labwired_verify` verdict.
