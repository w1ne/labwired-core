# STM32F411CEU6 climate node — firmware and stimulus smoke

An Arduino sketch for the climate-node board plus the committed engine smoke
that drives its analog channels. This is the Stage 3 executable example: the
board design is
`packages/board-config/test/fixtures/designs/stm32f411ceu6-climate-node/`,
its run manifest (`system.yaml`) is **generated** from that diagram, and
`io-smoke.yaml` proves the NTC, LDR and BME280 respond to engine stimuli with
the physics the device models state.

## The node

| Part | Wiring | Engine channel |
|---|---|---|
| `th1` NTC (B = 3950, R0 = 10 kΩ) | VBAT → NTC → **PA0** → R3 10 kΩ → GND | `th1.temperature`, ADC1 ch0 |
| `ldr1` LDR (10 kΩ @ 10 lx, γ = 0.7) | VBAT → LDR → **PA1** → R4 10 kΩ → GND | `ldr1.lux`, ADC1 ch1 |
| `u2` BME280 @ 0x76 | I2C1 SCL **PB6** / SDA **PB7** | `u2.temperature/humidity/pressure` |
| `oled1` SSD1306 @ 0x3C | I2C1 through the **J3** header | `oled1` (display artifact) |
| `d1` LED | **PA5** through R5 | PWM duty (verify oracle, not script-assertable) |
| `bz1` buzzer | **PA6** through Q1 | GPIO level |

Both sensors are the **top leg** of their divider, exactly as the engine's
`core/configs/devices/ntc_thermistor.yaml` / `ldr.yaml` formulas are written —
at 25 °C the NTC node sits at exactly Vref/2 = 2047 counts, and the ADC counts
rise with temperature. The sketch inverts the same math (Steinhart–Hart for
the NTC; the model's power law for the LDR).

**Display on J3 (recorded plan deviation).** The board pipeline has no
off-board representation (a placed module would be plated as a second 4-pin
header), so the SSD1306 is not on the copper: it is a system-level add-on wired
through `J3` (+3V3 / GND / PB6 / PB7). `system.yaml` is generated by
`packages/board-config/test/generate-node-system.test.ts` from
`prepareRunTarget(diagram, 'stm32f411ceu6-chip')` with the display appended to
`external_devices:` directly after `u2` — rerun that test with
`LABWIRED_REGENERATE_DESIGN=1` after any fixture change; without the env var it
is the drift gate for the committed file.

**One writer per ADC channel.** The NTC/LDR formulas already include their 10 kΩ
pull-downs, so the generated manifest deliberately carries **no**
`cosim_models` block for those nets: an analog-island half-model (pull-down
only) would otherwise clobber the kit's seeded level at every 100 µs
co-simulation boundary. `system.yaml` is the evidence; the regression tests are
in `packages/board-config/test/analog-island.test.ts`.

## Run the smoke

From this directory, with the built engine CLI (`labwired-cli 0.25.0`):

```bash
/home/andrii/src/labwired/.worktrees/stage3-climate-node-testing/core/target/release/labwired test \
  --script io-smoke.yaml \
  --firmware firmware/.pio/build/blackpill_f411ce/firmware.elf \
  --system system.yaml \
  --output-dir /tmp/opencode/node-smoke
```

`io-smoke.yaml` also carries `inputs:` with the same relative paths, so a plain
`labwired test --script io-smoke.yaml` works too. Expected tail:

```
NTC iter=10 adc=3633 mV=2927.7 temp_c=79.97
LDR adc=3912 lux=794.2
BME t=31.00 p=1002.0 h=60.0
ALARM 1
PASS  11/11 checks · io-smoke · 24000000 steps · ~4-5s
```

Two runs produce a byte-identical `uart.log` (sha256
`8cc750cdb9f8239246d6396ab05706ff8ec7db37284dc7a9665eec89929ed02f`), so the
transcript is deterministic.

## What the smoke asserts

Boot state (first iterations, 25 °C / 100 lx / BME defaults), then all three
modeled parts are stimulated at 15,000,000 cycles:

| Assertion | Meaning |
|---|---|
| `NTC iter=0 adc=2047 mV=1649.6 temp_c=24.99` | 25 °C is exactly Vref/2 on the model's divider; a dead ADC or an unseeded channel cannot print this |
| `LDR adc=3413 lux=99.8` | the model's 100 lx default through the firmware's inversion |
| `NTC iter=[1-9]… adc=3633 mV=2927.7 temp_c=79.97` | 80 °C NTC stimulus, Steinhart–Hart agrees |
| `LDR adc=3912 lux=794.2` | 800 lx stimulus |
| `BME t=31.00 p=1002.0 h=60.0` | BME280 temp/pressure/humidity stimuli read back through the Adafruit compensation |
| `ALARM 1` | 80 °C is over the 45 °C threshold (boot prints `ALARM 0`) |
| `display_region oled1 (0,0,128,8) min_ink: 1.0` | the solid header band the sketch repaints every iteration is fully inked at end of run |
| `expected_stop_reason: max_steps` | the run spends its declared budget |

Limits: LED PWM **duty** is not script-assertable (`gpio_duty` is an oracle
clause, not a test-script assertion) — that claim belongs to the verify receipt
in the stage plan. There is no buzzer sound model; the smoke proves the GPIO
level only.
