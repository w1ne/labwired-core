# TI LP-MSPM0G3507 LaunchPad UART0 smoke

**Demand rank:** MSPM0G3507 has no separate measured MCU rank in the survey.
The broader TI LaunchPad kit category measured 7% kit use. This is strategic
vendor expansion work, not a top-ranked MCU demand pick. ESP32 remains measured
rank 1 at 38%.

The bare-metal Cortex-M0+ firmware requests UART0 power, initializes its TX
controls, sets 115200 8N1, and writes `LP_MSPM0G3507_UART0_OK` through TXDATA.
The simulator loads the ELF at the
flash entry point and captures UART0 TXDATA after CTL0.EN and CTL0.TXE are set.
This is a focused LaunchPad slice: the chip profile includes its flash/RAM
geometry and the UART0 TX register path.

The simulation does **not** model MSPM0 GPRCM power state, IOMUX/pad routing,
UART timing/FIFO behavior, GPIO, ADC, timers, or the board's sensors/LEDs. The
serial marker proves the core booted and reached the UART TX path; it does not
prove an electrical waveform at XDS110. The descriptor intentionally makes no
claim about the other LaunchPad hardware.

## Run

```sh
rustup target add thumbv6m-none-eabi
examples/lp-mspm0g3507-launchpad/ci/test.sh
```

The committed smoke logs and structured result are in `evidence/`.

## Copy-paste UART0 bring-up (TI DriverLib)

For a physical board using the default J21/J22 XDS UART jumpers, this minimal
TI DriverLib setup prints to the XDS110 serial console:

```c
#include "ti_msp_dl_config.h"  // Generated by SysConfig: UART0, PA10/PA11, 115200 8N1.

int main(void) {
    SYSCFG_DL_init();  // Generate UART0 on PA10/PA11 at 115200 8N1 in SysConfig.
    const char message[] = "LP-MSPM0G3507 UART0 ready\r\n";
    for (unsigned i = 0; i < sizeof(message) - 1; ++i)
        DL_UART_transmitDataBlocking(UART0, message[i]);
    for (;;) {}
}
```

Generate `SYSCFG_DL_init()` from TI SysConfig with UART0 routed to PA10/PA11;
the simulator smoke uses direct register writes instead of DriverLib.
