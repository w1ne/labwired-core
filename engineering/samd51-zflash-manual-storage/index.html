    Opt-in SAMD51 manual storage: qualified source boundary

    Backported from CrispStrobe/labwired-core PR249/PR252. The source and CI receipts below remain bound to that fork; this tree carries the model, the instruction-boundary commit, the opt-in factory and the hosted fixture test. The hosted builder, mutation harness and exact external checkout pins remain in the fork and are not part of this chunk.

    This lane follows the qualified public source census. It adds an explicitly selected manual NVMCTRL slice, CMCC controls and a hosted caller of the real public ZFlash implementation. The selected guest qualification is recorded below. PR249 merged as 7da375fc8ae4f61c191502a542a2d92e6ab9f948 after all 29 enabled exact-head checks passed, with seven source-declared conditional skips. The landed tree and ordered parents match the qualified composition. Default chip descriptors and consumer pins are unchanged.

    The new factory names are samd51_nvmctrl_manual_storage at 0x41004000 and samd51_cmcc_control at 0x41006000; both refuse IRQ/config overrides. The profile requires exactly 512 KiB of zero-based flash, 512-byte pages and 8 KiB erase blocks. Only the final 32 KiB storage window admits array stores and addressed operations. Other regions and unsupported modes refuse explicitly; that simulator boundary is not a claim that silicon produces the same error.

    Register facts are reviewed against Microchip's SAM D5x/E5x datasheet DS60001507F, sections 11.6/11.10 and 25.6.6/25.8. No vendor implementation or register header is copied. Cache controls do not model cache contents or physical cache timing. This slice excludes fuses, boot protection, region locks, automatic writes, ECC, NVM interrupts, auxiliary rows, physical timing and reset persistence.

    Manual aligned 32-bit stores populate a page buffer with the documented 64-bit holding-register transitions and address updates. Main flash stays unchanged until an admitted WQW command commits its sixteen-byte window. EB erases one 8 KiB block; PBC clears buffering. The key and busy admission, READY, DONE, PROGE/ADDRE and their supported W1C operations stay distinct. Unsupported commands refuse rather than being mislabeled as invalid hardware commands.

    Four instruction-boundary services provide a finite deterministic busy interval, not measured silicon latency. Pending operations end Cortex-M batches; the existing flash-operation predicate also excludes JIT execution. Commit and READY publication follow in the same boundary, against the actual bus backing. Default buses take the absent-controller path. Unsupported concurrent array writes refuse; this does not implement an AHB stall protocol.

    Real-driver guest and mutation qualification

It reuses the qualified include-only ZFlash compiler producer and links that actual object with an authored boot-only caller, real CPS instructions and freestanding byte-copy/clear routines. It supplies no invented Flash implementation. This is not a complete CODAL/PXT runtime or its paired fiber/IRQ service implementation.

    The linker reserves the complete storage window outside executable/load data. The observer declares its initial dirty test block and neighboring canaries before execution. Only actual guest-driver calls and model operations may subsequently change them. Six ordered checkpoints require geometry, real erase, 32-byte programming, an eight-byte partial window, actual -1/-2/-3 driver refusals and re-erase, preserving all neighbors. Single-step observation follows all four original method entries and LR returns with actual r0 results; a separate fresh advance-API run checks every checkpoint's backing state.     Scoped follow-up contracts

    The existing DMA API still borrows caller-owned buffers. Preserve the original masked async terminal interval, the newer finite unmasked intervals and the expected premature-release witness; none establishes enforced ownership or unlimited lifetime. Keep the qualified DMA boundaries when requalifying a new engine.

    These are task contracts, not ownership claims. Refresh heads, open PRs and ownership before starting. Keep admitted sources, notices, original failures, GC/DMA regressions and all bounds. Completed source-qualified slices are not permission to replay successful originals.

    1. Consumer engine adoption — complete. Codal PR72 adopted the explicitly reviewed engine79071f69 with all 22 enabled checks and 21 case audits. Historical census/profile identities remain unchanged; unrelated default descriptors were not enabled. No browser adoption follows.
    2. Actual RAFFS/settings composition — finite checkpoint complete. Codal PR74 qualifies actual filesystem/settings with real GC/services, both profiles, 1,871 checks, object remount and eight specific mutation/profile cases. Subsequent separate contracts cover compaction, the current source census and modeled retained-backing reset. Inspect each final qualification record. CPU/core-system reset over the same Bus leaves peripheral models live; engine restart/backing reopen, interrupted operations and power loss require new explicit contracts.
    3. Full board and IRQ/service configuration. Separately census the remaining shared-header dependencies and an actual generated full-board configuration. Do not infer USB1 from the service profile or core defaults. Trace required functions to admitted public implementations; model and qualify each missing behavior in an owned lane. The boot-only CPS helpers here do not qualify full CODAL paired fiber/IRQ semantics. The held USB/QSPI stubs and feature-disabled service fixture do not establish the original board configuration. Establish actual QSPI source use before declaring it required; qualify enabled USB only after its configuration is fixed. Preserve that gap until actual enabled configuration and affected guests pass; disabling required features cannot close it.
    4. Additional controller semantics or downstream adoption. Fuses/protection, automatic writes, ECC, cache contents/timing, NVM interrupts and reset/ persistence each need a separate precise model contract and affected guest qualification. Native Arcade, WASM/installed Lite and performance require their own exact engine/package/consumer evidence after source integration. No physical, release or complete storage-runtime conclusion follows from the selected flash case.

    All source/model changes require affected clean guest qualification and every enabled exact-head check. Acquire official originals once after metadata admission and audit retained bytes with standalone readers, without replay. Documentation-only follow-ups use the applicable source-policy/docs checks; do not manually dispatch another unchanged ARM guest merely to update prose.
